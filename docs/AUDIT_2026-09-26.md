# Audit: naming and annotation, 2026-09-26

The whole game was checked against FOUNDATIONS §6, CLAUDE.md and what became `docs/CONVENTIONS.md`: 58 source files (about 15,300 lines), plus the tools and tests.

**Read-only:** no source file was changed (the code hold is in effect). The fixes below are a plan for the owner's go-ahead.

**How it was checked:** scripts over every file (headers, name styles, design-section references, stale words, comment density), then the flagged spots read by eye. Figures are from the scripts. Judgements, such as whether a stretch needs a note, are Claude's, from reading.

## Summary

**Naming is excellent and consistent:**
- all 565 file-scope functions are PascalCase; the one exception, `wWinMain`, is required by Windows;
- all 312 globals carry `g_`;
- every enum follows one rule: plain enums use prefixed ALL_CAPS values, `enum class` uses PascalCase;
- struct members and locals are camelCase.

The one split is in constants: ALL_CAPS in most of the code (about 150), `kName` in the synthesis files (about 64), `g_` for large constant data (15), and five stray `k` tables. It's recorded in CONVENTIONS.md as allowed, with **no renames proposed**.

**Headers exist everywhere and are well written,** but the four required fields (what, cost, layer, design section) are complete in only about a dozen files. Most headers say *what* well; many omit cost and layer.

**References:** every `DESIGN.md` section referenced from code exists (71 sections and 23 parts checked). But a few comments name removed files and features, and `DESIGN.md` itself has stale passages.

**No `TODO`, `FIXME` or `XXX` markers, and no brand names in code.**

**Complete, the models:** collide.h, facetmesh.h, groundmesh.h, jobs.h, strtable.h, terrain.h.

**Stand-alone `.cpp` files and tools** (no `.h` to carry the header):
- `game.cpp`, `main.cpp` and `tests/tests.cpp` lack some fields;
- most tools have one- or two-line headers, fine for small scripts, thin for `natural_textures.py` (985 lines) and `facet_preview.cpp` (893 lines).

### 2. Headers that no longer describe their file
- `render.cpp` / `render.h`: "chunk meshing". Meshing moved to `groundmesh.cpp`; render uploads the meshes. The header also omits most of what the file now holds: shaders and their cache, shadows, bloom, the post pass, the UI atlas.
- `main.cpp`: lists `persist.h/persist.cpp`, which was split in M0.9 into `gamefiles`, `savegame` and `settings`.
- `tests/tests.cpp`: describes "the save format (v5 round trip and legacy v4)" and "the chunk mesher". Saves are walkgrid v1 now, the mesher is the facet mesher, and the tests also cover the sound system, terrain, collision and more.

### 4. Stretches that would benefit from one line each
Most long uncommented stretches read clearly (parsers, menu layout, simple loops). These three don't:
- `sfx_synth.cpp`, the recipes (from about line 1164): levels, filter widths and pitch floors with no pointer. One line per recipe naming its SOUND_PALETTE section.
- `worldfile.cpp` (about line 78): the run-length encoding of chunk cells, state and data. One line on the layout.
- `render.cpp` (about line 1547): the FNV-1a constants in the shader cache key. One line naming the hash.

### 5. Documentation of record (the owner's call to correct)
- `DESIGN.md`:
  - Part IV and the build section describe `mesher.cpp` and `shapes.cpp`, which aren't in walkgrid;
  - the build lines list `persist.cpp`;
  - it says "twenty-four source files" (there are 58);
  - the tests paragraph (about line 546) names the old modules and save versions;
  - §11.2 describes a colour-vision setting whose file was removed with the pulse (also in `docs/research/ACCESSIBILITY.md`).
- `CLAUDE.md`, Threads: "the job threads (2 today; they may be sized from the processor count)". They are sized now: `clamp(cores − 2, 1, 4)`, per `jobs.h`.

### 6. Structure, noted, not a writing issue
`render.cpp` is 2,270 lines holding several systems (device setup, shaders and cache, shadows, bloom, post, sky, the UI atlas), against "one system per file". Splitting it would be a planned engine step: code moved, not rewritten, and the owner's call. It's listed here only so it isn't forgotten.

## Fix plan (for approval; notes only, no behaviour change)

One step, "notes pass", touching comments only. Each change is a small change in the SOP's sense. It's verified by all five checks, and by a diff showing only comment lines changed.

| File | Change |
|---|---|
| the 24 headers in finding 1 | Add the missing fields (cost, layer, design section) |
| render.cpp, render.h, main.cpp, tests/tests.cpp | Rewrite the stale headers (finding 2) |
| world.h, render.cpp, common.h, render.h | Fix the removed names (finding 3) |
| sfx_synth.cpp, worldfile.cpp, render.cpp | The one-line notes (finding 4) |
| DESIGN.md, CLAUDE.md | Correct the stale passages (finding 5), if the owner agrees |

Then a second, separate step: `tools/check_notes.py` (CONVENTIONS.md §3), added to the checks, so none of this drifts again.
