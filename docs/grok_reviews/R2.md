# Grok R2 (weather): appraisal

Delivered 2026-09-26. **Only sections 3–12 reached Claude**: the paste starts part way through section 2 (the weather state's fields and the jet-stream note), so sections 1–2 are missing. Appraised by Claude against the code; Grok's text isn't kept.

**Grade: good as a skeleton, wrong in several details.**
- Its structure is what we want: a small weather state, kinds as a data table, slow transitions with weighted next kinds, and one precipitation effect.
- It misread two knobs (fog and exposure), got overcast light backwards, and overstated how much sound already exists.
- It forgot saving and determinism.

## Claims checked against the code

| Grok said | True? | What the code says |
|---|---|---|
| Weather can scale "fog start / fog end" to shorten the view in rain and storms | Misread | Those two numbers are the **edge of the loaded world** fading into the sky (`fFog.x/y`, set from render distance, D64), not weather fog. Pulling them in would move the world's edge closer and waste the loaded ground. Weather fog belongs in the haze term instead (`FogAmount`'s `exp(-dist/260)` and its 0.45 cap): shorten its scale and raise its cap in rain. |
| Lower exposure in storms (0.65) | Doubtful | Exposure stands in for the eye adapting, and it lifts only real night. Dimming the sun and sky is the physical route; lowering exposure as well would darken twice. Leave exposure to the day clock. |
| Overcast: sun 0.55, ambient 0.70 | Backwards | Under overcast, direct sun (and its shadows) all but disappears and the sky's light becomes most of what there is. With these numbers, overcast would still cast crisp shadows. Overcast wants the sun near 0.1, the ambient kept up, and colours greyed. The same goes for rain and storm. |
| Snow as an ordinary kind | Needs a rule | The world is on its equator with no seasons or temperature (DESIGN Part XIII). Snow only makes sense on high ground (snow tops start above 45 cells), so snow needs a condition such as altitude, or it waits for climate. Grok's own open question (rain and snow together?) points at this without answering it. |
| Rain and snow as "a full-screen pass after the main scene" | Adapt | The rule is per-pixel tricks, not extra passes (CLAUDE.md). There is already a post pass with scene depth (render.cpp, "scene + depth in"), so precipitation goes inside it, as a branch that costs nothing when dry. Its own depth fade near the camera is then free. |
| Sound: "no new audio code paths"; "the synthesizer already knows how to interpret" precipitation | False | Nothing in the synth knows about rain. A rain bed (filtered noise that breathes), drips and a storm rumble are new recipes in `sfx_synth.cpp`, harmony-locked (tonal parts from the safe pitch sets) and checked by `sound_demo.sh analyze`. Weather nudging the three axes is also a new input to the world-sound system. The ideas are good; they just aren't free. |
| Update weather "on a background thread" | Unneeded | Blending a dozen numbers once a game minute is nothing; it belongs on the main thread with the day clock. |
| Clouds use existing cover knobs | True | The covers are constants today (`CIRRUS_COVER`, `CUMULUS_COVER`, render.cpp) passed through `fClouds` every frame; turning them into weather values is easy. |
| Not mentioned: saving | Missing | The weather state has to be saved with the world (like the day count: a tag in the game's section of the save, `DAY1` style), or every load resets the sky. |
| Not mentioned: determinism | Missing (asked) | Choosing the next kind from a seeded hash of (world seed, day, minute) makes weather repeatable and needs no random state saved beyond the current blend. |

## Verdicts

| Part | Verdict |
|---|---|
| Weather state + kinds as a data table + weighted next kinds + slow blend | **Keep**: this is the design. |
| The six-kind table | **Adapt**: fix overcast, rain and storm light (sun down, ambient kept); drive haze, not the world-edge fade; leave exposure alone; snow only with an altitude or climate rule. |
| Precipitation effect | **Adapt**: inside the existing post pass, gated by a setting. |
| Sounds | **Keep the ideas, as new recipes**: rain bed, drips, rumble, through `sfx_synth` with the harmony checks. |
